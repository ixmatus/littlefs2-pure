# Verification map

Claim to artifact, with each artifact's blind spot named. A clean result speaks only to what the checker can see; this map exists so nobody has to reconstruct that boundary from the test tree. Tracker ids in parentheses are this repository's issue handles as of 2026-06-11 and decay faster than the prose around them.

| Claim | Artifact | What it cannot see |
|---|---|---|
| Images the C oracle wrote read correctly here (bit accuracy, read direction) | `tests/conformance.rs` over the seven images in `tests/vectors/` (see `conformance-vector-corpus`) | Scenarios with no vector: oracle compacted directories, delete observed across a mount, multi step move gstate, user attributes, deep CTZ chains (lfs-761); a single geometry |
| Images this crate writes read correctly under the C oracle (bit accuracy, write direction) | `tests/roundtrip.rs` driving `tools/verify_image` (the pinned oracle compiled as a verifier) | The gate is read only; the oracle never writes into our images, so mixed writer histories are unexercised (lfs-jdk). The suite currently passes silently when the verifier binary is missing (lfs-4d4, lfs-wee) |
| A power loss at any modeled interruption point leaves the previous state mountable and intact | Torn write sweeps: `tests/power_loss.rs`, `tests/dir_split_torn.rs`, `tests/pending_softtail_torn.rs`, `tests/badblock_reloc_crash.rs`, `tests/pending_badblock_reloc.rs` | The interruption model: tears land at program call boundaries over `MemStorage`. Tears inside a program window at cache boundaries, and partial program landings as NOR hardware would leave them, are not generated (lfs-xzt, lfs-e2a, lfs-hki). This is the README disclosure's named failure mode; the frame is `pillai-2014-crash-consistency` |
| NOR program semantics (one to zero only, alignment) are honored by the write paths | `tests/nor.rs`, `tests/review_shrink_append.rs` under `StrictNorStorage` and `NorAlignedStorage` | Suites that run only on permissive RAM storage say nothing about NOR behavior; that gap shipped a corruption bug once (`failure-setlen-nor`) |
| CRC matches the published CRC-32/ISO-HDLC anchor and the C table byte for byte | `external_crc32_check_value` in `src/crc.rs`; `tests/property_crc.rs` against a bit by bit reference; `src/verify/crc_proofs.rs` (Kani, bounded slices) | Kani's slice bound; property inputs are sampled, not exhaustive |
| Tag encode then decode is the identity; classification is total | `tests/property_tag.rs`; `src/verify/tag_proofs.rs` (Kani, exhaustive over the 32 bit tag space) | Nothing within the tag word itself; cross tag invariants (XOR chains) live in the metadata suites |
| Metadata commit accept or reject is total; the reader never panics on arbitrary bytes | `tests/property_meta.rs`; `src/verify/meta_proofs.rs` and `src/verify/commit_proofs.rs` (Kani, bounded geometries); fuzz targets `meta_reader_parse`, `mount_image`, `superblock_parse`, `tag_decode`, `ctz_struct_decode`, `path_validate` (CI smoke job) | Kani geometry bounds; fuzz coverage is whatever the corpus reached, a sample and not a proof |
| The allocator never hands out a live block | `tests/review_lookahead.rs`; churn suites (`tests/wear_leveling.rs`, `tests/power_loss.rs`, `tests/atomic_move.rs`) would surface a double allocation | No direct proof; the property is enforced by construction (the cache over approximates in use blocks) and witnessed, not proven |
| CTZ block resolution agrees with the full walk | `tests/review_seek.rs` (every index of a 200 block chain against the walk oracle); `tests/property_ctz.rs` | The property oracle shares its capacity formula with the implementation (lfs-9z5), so a shared formula error would pass |
| The no_std no_alloc floor builds for the ship target | CI: `cargo build --target thumbv6m-none-eabi --no-default-features` | Compiling is not running; no hardware in the loop |

## Reading the map

Two structural honesty rules govern updates. First, a new correctness claim enters this table in the same slice that ships it, with its blind spot filled in; a row without a blind spot is a row not yet thought through. Second, when a gap listed here closes, the row and the corpus entry are updated together, and the README disclosure is reconciled if the named failure mode changed shape.
